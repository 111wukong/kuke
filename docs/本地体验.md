## 先试 AI 课堂（这是新加的那块）

左侧导航 → **AI 课堂** → 选一个考点 → 开一节课。

**建议第一个选「数据库和 DBMS 的区别」**（`k-dbms`）——它最简单，
正好能看出 AI 到底在干什么。

看这几处：

1. **黑板上的 SQL 是真的跑出来的**。老师会调 `run_sql`，结果表直接贴在右边。
   不是它编的 —— 每次都是在一个全新的内存库上真执行。
2. **说一句「没听懂」**。它会切到「答疑重讲」：**三个学生全部安静**，
   老师换个说法重讲，而且**不许出题**。你会在对话流里看到两条提示：
   「这一轮是答疑，3 位同学已安静」和「这一轮本来要出题，被换成了理解确认」。
3. **看左边「引导占比」**。focus / probing / telling 三个数字。
   如果 telling 特别高，说明老师在念答案而不是引导你。
4. **拖着看图**。让老师画个曲线（比如问它 B+ 树高度随阶数怎么变），
   图下面的滑块可以拖，曲线实时变，**坐标轴是钉死的**——不钉的话整张图会跟着手抖。
5. **等作答的时候注意底部输入框**。它会被禁用，并写清「先把上面那道题交了，再插话」。
   这不是 bug，是刻意的：老师不该同时被「等你答题」和「你插的话」两条线拉扯。

三种模式的区别：

| 模式 | 是什么 |
|---|---|
| 一对一讲透 | 只有老师。快、聚焦 |
| 多人课堂 | 老师 + 三个水平不同的学生。他们会吵起来，也会**说错** |
| 研讨课 | 不讲课，直接抛一个开放问题让他们争 |

> 三个学生不是「不同性格」的摆设：**后进生手上真的只有一句摘要**，
> 优等生拿到正文 + 示例 SQL + 依赖关系。资料量不同 → 分歧是结构性的，不是演出来的。
> 而且学生手里**没有「写完整解答」的工具** —— 会跑 SQL 不等于会写解法。

## 已知的两处小毛病

1. **浏览器冒烟的 2 条断言在 macOS 上偶发失败**（主题对比度那条）——
   和 `getComputedStyle` 返回的颜色格式有关，Ubuntu 的 CI 上是绿的。
2. **前端首屏会有一次「加载中」闪烁** —— `web/dist` 是构建产物，
   改了前端代码要重新 `npm run build` 才生效。
