# 库课 · 设计说明

> 面向高校师生的数据库课程学习平台。教师对学生有完整的管理权限。
>
> 本文回答三件事：**核心功能模块是什么、页面怎么组织、技术上怎么实现**，
> 以及每一处设计取舍的理由。

---

## 〇、先说清楚：为什么不是「又一个 SQL 练习网站」

参考项目 `kaoyan-math-tutor`（考研数学 AI 自学系统）给了一套很成熟的骨架：
知识树 + 有向依赖图 + 结果集判题 + FSRS 间隔重复 + 教师管理台 + 审计日志。
这套骨架我基本照搬了。

但**数据库这门学科有一个数学没有的东西：它能真的跑起来**。

数学题的「对错」最终要靠人判断（所以考研数学项目用 AI 批改主观题）。
而数据库题的对错，可以**由数据库引擎自己回答**：

| 问题 | 数学 | 数据库 |
|---|---|---|
| 学生写的对不对？ | 需要人看过程 | **跑一遍，比结果集** |
| 索引生效了吗？ | — | **问优化器：`EXPLAIN QUERY PLAN`** |
| 这个调度可串行化吗？ | — | **建优先图，检测环** |
| 这个分解无损吗？ | — | **矩阵法（chase）算出来** |
| 这个关系到几范式？ | — | **按定义逐条验** |

所以本站的技术核心不是「怎么让 AI 批改」，而是**怎么让引擎来判分**。
下面所有设计都围绕这一点展开。

### 1.2 三个「数据库特有」的模块，值得单独说

#### ★ SQL 闯关：判题不比对 SQL 文本，比对结果集

同一道「查出所有姓张的学生」，下面四句都是对的：

```sql
SELECT * FROM student WHERE name LIKE '张%';
select * from student where name like '张%'
SELECT id, name FROM student WHERE substr(name,1,1) = '张';
SELECT * FROM student WHERE name GLOB '张*';
```

文本比对会把后三句判错 —— **那是在考拼写，不是在考 SQL**。

所以判题流程是：把参考答案和学生的答案**分别在同一份数据集上跑一遍**，
比对两份结果表。三个必须处理的坑：

| 坑 | 处理方式 |
|---|---|
| **行序** | SQL 标准里没有 `ORDER BY` 的结果集无序 → 默认按多重集比对；题目含 `ORDER BY`/`LIMIT` 时用 `order_matters=1` 强制按序 |
| **列名** | `COUNT(*)` 和 `COUNT(*) AS 人数` 数据一致 → 默认只警告；题目明确要求列名时用 `require_columns=1` |
| **值类型** | SQLite 是动态类型，`1` / `1.0` / `'1'` 要能等价 → 先做数值化尝试再比 |

还有一条容易被忽略的：**DML 关卡没法比结果集**。
`INSERT`/`UPDATE`/`DELETE` 的参考答案不产生结果表。
这类关卡走另一条路径：把学生 SQL 和一段 `check_sql` 拼成一条提交，
让 check 看到学生改过的状态，返回真值即通过。

#### ★ 范式实验室：验性质，不比对答案

分解题的正确解**通常不唯一**（最小覆盖不唯一 → 合成结果不唯一）。
拿一个参考答案做字符串比对，会把完全正确的分解判错，
而学生根本无从察觉 —— 他会以为自己错了，然后去猜答案。

所以判分是验**性质**：

```
① 覆盖全部属性  ② 无损连接（矩阵法/chase）
③ 3NF 时还要保持函数依赖  ④ 每个关系达到目标范式
```

`answer.schemes` 在数据文件里的作用退化成「给前端展示一个可行解」，
判分逻辑根本不读它。

#### ★ 索引实验台：答案由 `EXPLAIN QUERY PLAN` 给出

学生从四个索引方案里选一个。服务端对**每个选项真的建一次索引、
真的问一次优化器**，然后把执行计划原样回给前端。

页面上会把每条计划展示出来 —— 学生不只是在「对答案」，
而是在看数据库自己怎么说：

```
A  CREATE INDEX idx_s_dept ON student(sdept)
   → SEARCH student USING INDEX idx_s_dept (sdept=?)   ✓ 走索引
B  CREATE INDEX idx_s_sage ON student(sage)
   → SCAN student                                      ✗ 全表扫描
```

还有一类题故意让**所有索引都没用**（`LIKE '%键盘'` 前导通配符），
正确答案是「以上都不能」—— 这教的是「索引不是万能的」。

### 1.3 教师权限模型（需求的核心）

需求原话是「老师对学生有完全的管理权限」。这句话必须落成可执行的规则，
否则「完全」会变成「对所有人」。

```
┌── 教师能对自己名下的学生做任何事 ────────────────────────┐
│  建号 / 改资料 / 改学号 / 重置密码 / 强制下线             │
│  停用 / 启用 / 删除                                       │
│  查看全部学情（作答明细、他写的每一条 SQL、错题、复习进度）│
│  布置作业 / 批改 / 写评语                                 │
└──────────────────────────────────────────────────────────┘
┌── 教师不能 ──────────────────────────────────────────────┐
│  管理别的教师的学生（越权）                               │
│  把自己提为管理员（提权）                                 │
│  管理任何 role='teacher' 或 'admin' 的账号                │
│  看到学生的密码哈希（连脱敏形式都不给）                   │
└──────────────────────────────────────────────────────────┘
```

**「自己名下」怎么判定**（两条都要，缺一条就会出问题）：

```
scope(教师) = 他创建的账号（users.created_by = 他）
            ∪ 他名下班级的成员（class_members）
```

- 只算班级成员 → 教师批量建号后还没分班的学生，他管不了
- 只算 created_by → 学生凭邀请码自己入班的，他管不了

**越权返回 403 而不是 404**：如果「存在但无权」返回 403、
「不存在」返回 404，那 403 就成了一个**存在性探测器** ——
可以拿它枚举全校学号。所以顺序固定：先查存在性（404），再查权限（403）。

- `/classes` 一个路由两种形态：学生看到的是「加入班级」，
  教师看到的是「班级管理」。靠接口返回的角色分流，不靠前端角色判断。

这样做的理由：**「我到底在哪个页面」这件事要清晰**。
拆成 30 个路由的话，学生和教师会各自迷路。

**三个关键交互决定**：

1. **路由保活**。切走的页面不卸载，只是 `display:none`。
   学生在 SQL 实训场写了一条长查询，去知识点页查个表名，回来
   编辑器还是原样 —— 这个应用的核心用法就是来回切，卸载等于打断。

2. **站内链接默认新标签页**。知识点里的「拿去实训场跑」、
   题目里的「查看相关知识点」都会开新标签，原页面的滚动位置、
   展开状态、编辑器内容全都留着。

3. **答题反馈即时且不自动跳**。答完立刻出判定和解析，
   但**必须用户主动点「下一题」**才走。自动跳会让人来不及看解析，
   那这一题就白错了。

### 3.1 技术选型

| 层 | 选择 | 为什么 |
|---|---|---|
| 后端 | **Fastify 5** | schema 校验内建，把「参数不对」挡在业务代码之前 |

### 3.3 关键技术点

#### SQL 沙箱（本项目的技术心脏）

```
学生 SQL
   ↓
① sqlGuard.analyze        静态分析：切分语句、拦危险语法、给提醒
   ↓                       （ATTACH / load_extension / sqlite_master / 危险 PRAGMA）
② 提交给 worker 线程       每次任务新建一个内存库，灌入数据集
   ↓
③ 主线程 4 秒超时           超时 → terminate() 强杀 → 换一个新 worker
   ↓
④ 结果集回传               列名 + 数据 + 耗时 + 提醒
```

**为什么必须跑在 worker 里**：better-sqlite3 是同步 API。
在主线程上跑一条 `SELECT * FROM a,b,c,d,e`（五表笛卡尔积）
会把整个事件循环钉死几十秒 —— 期间**所有**学生的所有请求都不响应。
`terminate()` 是唯一能打断同步 C 代码的手段。

**为什么超时后要换 worker 而不是继续用**：terminate 是强杀，
worker 可能死在任意一行，它那份内存库的状态不可信。
复用一个刚被强杀的 worker，下一题可能读到上一题的残留表。

**为什么每次任务都新建内存库**：隔离。
学生 A 的上一条 `INSERT` 不能影响他这一条 `SELECT` 的判题结果。
用完即弃是最省心的隔离，而代价（建库 + 灌几百行）是毫秒级。

#### 多主题：为什么是 CSS 变量而不是 JS 注入

Tailwind v4 的 `@theme` 把每个 token 编译成 `:root` 上的 CSS 变量，
工具类编译成 `color: var(--color-fg)` 这种**间接引用**。
所以「换主题」= 在更高优先级的选择器里重定义同一个变量：

```css
:root                          { --color-fg: #e9ebf4; }   /* 优先级 (0,1,0) */
html[data-theme="paper"]       { --color-fg: #1c1917; }   /* 优先级 (0,1,1) 赢 */
```

不需要 `!important`，也不需要把颜色搬到 JS 里运行时注入。
颜色由 `index.html` 里一段**内联脚本**在 bundle 之前挂上 —— 首屏不闪。

**三个不显然的地方**：

1. `--color-veil` 是**唯一一个明暗主题取值方向相反**的令牌。
   全站「在当前底色上叠一层」的地方都走它：暗色下它是白（叠亮），
   亮色下它是黑（叠暗）。原来这些位置写的是 `bg-white/5` ——
   亮色主题下白叠白，**卡片边界会凭空消失**，而页面依然「正常渲染」。
   这是最阴的一类缺陷：元素在、颜色对、只是看不见。

2. **亮色主题的强调色整体加深一档**。深空的 `#22d3ee` 放在白底上
   对比度只有 1.9:1，根本读不出来。所以宣纸的 cyan 是 `#0e7490` 这个量级。

3. **亮色主题不挂 WebGL 背景**。霓虹赛博网格画在暖白底上会变成
   一片灰蒙蒙的脏点。亮色下改用 CSS 层的淡色光晕 + 细网格。

4. **主题不只管颜色，也管字体**。砚秋 / 砚晨这两套古风主题会把
   `--font-sans` 换成 `var(--font-kai)`（楷体），并把根字号抬 3.5%。
   见下一节。

#### 古风主题与楷体：字体为什么会静默失效

古风这个需求，**光换配色是做不出来的**。深棕底 + 朱砂色 + 黑体字，
得到的只是"一个深棕色的普通界面"。字体才是主要载体。

所以砚秋 / 砚晨会把整站字体换成**霞鹜文楷**（LXGW WenKai，楷体）。
三个不显然的地方：

1. **不能引 CDN，必须自托管**。部署形态是「一个学校一套服务、
   学生走公网访问」，而中文 webfont 的公共 CDN 在国内的可用性
   不足以托付一个教学系统 —— 字体挂了，古风就没了，
   而页面一切正常，没有任何报错。

2. **不能一个文件搞定，必须切片**。6763 个汉字就是一个 4MB 起
   的 woff2。所以按 `unicode-range` 切成 97 片，
   浏览器**只下载页面上真正出现的那几片**（实测一个页面 6 片）。
   合并成一个大文件反而更慢：每个用户都得下完 4.3MB 才看见第一个字。

3. **字体栈里 webfont 后面必须跟系统楷体**。自托管字体是 GB2312
   子集，落在 `unicode-range` 之外的字不会命中任何 `@font-face`，
   浏览器会**沿着字体栈往下走**。栈里下一项要是 `serif`，
   Linux 上就变成 Noto Serif —— 同一个标题里「数据库」是楷体、
   「麒麟」是宋体，一眼就看出是坏的。

排版也要跟着补偿：楷体的笔画比黑体细、字面收，同样的 px 下视觉上
小一号。古风主题把根字号抬 3.5%（Tailwind 的字号/间距全是 rem，
改 `html` 一个值等于全站等比放大），行高从 1.7 放到 1.78。
用百分比不用 px —— 写 `font-size: 16.5px` 会把用户在浏览器里设的
字号偏好一并覆盖掉，那是无障碍问题。

> **这一块踩过的坑值得记**：字体出错**不会有任何断言变红**。
> 页面照样渲染、布局照样正确、截图里文字照样清晰，只是从楷体
> 变成了黑体。而颜色错了截图能看出来。
> 所以 `tests/fonts.mjs` 专门守四件事：资产与 CSS 双向对齐、
> 楷体栈有系统兜底、`themes.ts` 与 `index.css` 的「哪套主题用楷体」
> 一致、`unicode-range` 不重叠。
> 另外 `tests/browser.mjs` 里有一条**真浏览器**断言 ——
> 静态检查查不出「字体文件 404 / unicode-range 写错 / CSP 拦了
> font-src」，只有真浏览器能量出「到底有没有用上」。

#### 去「AI 味」：层级该由结构表达，不该由效果表达

这一节记录 2026-10-01 那次视觉语言调整。起因是一句反馈：
**"整个界面的设计 AI 味太重了"**。

先要把"AI 味"翻译成可操作的东西，否则只能凭感觉改。做完清点，
它的具体表现是这些（都是可数的）：

| 症状 | 调整前的量 |
|---|---|
| 玻璃拟态（半透明 + backdrop-blur + 四层叠加） | 卡片、面板、侧栏、顶栏……125 处 |
| 渐变（按钮、标题、进度条、徽章、描边） | 46 处 |
| 光晕 / 发光 | 49 处 |
| 每张卡片标题前一个**不同颜色**的装饰图标 | 63 处 |
| 超大圆角（16px 的 `rounded-2xl`） | 7 处 |
| 会动的背景（WebGL 透视网格 + Canvas 星尘 + 三团漂移光斑） | 默认主题就有 |

**根因只有一句话：用"效果"表达层级，而不是用"结构"表达。**

去看真实的生产级设计系统，它们在这件事上的答案高度一致：

- **Radix Colors** 用 12 级色阶把角色分开：
  1–2 背景 / 3–5 组件底（普通·悬停·按下）/ 6–8 边框
  （非交互·交互·焦点环）/ 9–10 实心 / 11–12 文字（低对比·高对比）。
  **每一级只干一件事**，所以永远不会出现"这块该用什么颜色"的犹豫。
- **Semi Design** 的阴影定义是「浅阴影，**通过 border 模拟的扁平阴影效果**」，
  并且明确写「在暗色模式下，我们通常用**背景色**来区分前后层级」。

两条说的是同一件事。于是调整是：

**1. 面分成两套，而不是一套通吃。**
```css
.panel   /* 实色面 + 1px 边框 —— 卡片、面板、区块，默认都用这个 */
.glass   /* 半透明 + 模糊 —— 只给弹窗、下拉、抽屉、sticky 顶栏 */
```
之前**所有**卡片都是 `.glass`。单看一张很好看，铺满一屏就是灾难：
每张卡都在"浮着"，于是没有任何一张是浮着的，层级反而消失。
浮起是**稀缺资源**，只能给真正浮在内容之上的层。

`--panel` 的取值也踩了一次：一开始直接写 `var(--color-ink-800)`，
结果砚秋主题的 ink-800 是 `#6b432a`（旧木家具的亮棕），
压在 `#2b1810` 的页面上是一块突兀的亮板子。
改成**按模式分两步**：暗色把 ink-1000 和 ink-800 按 72:28 混，
亮色直接用 ink-800（那本来就是各亮色主题的白纸面）。

**2. 效果收敛。**
- 主按钮：渐变 + 外发光 + 悬停扫光 + 按下位移 → **实色 + 悬停变亮 4%**
- 发光只保留一处语义：**键盘焦点环**。发光该表达"你在这里"，
  不是"这很重要" —— 一屏三个发光按钮等于三个都在喊"看我"。
- 渐变只保留给**图表**（那里颜色本来就没有层级语义，
  渐变是把同一色系连起来，是信息不是装饰）。
- 装饰性图标留着（它确实帮助扫读），但**颜色收掉**：
  在 `SectionTitle` 里用 `[&>svg]:text-fg-faint` 统一压成弱化色。
  颜色在真实产品里是有语义的（危险=红、成功=绿、当前项=强调色），
  拿它给纯装饰分类，等于把语义稀释掉。
- 圆角整体收一档：卡片 12→8px、控件 8→6px。
  大圆角是"消费级 App"的语言，数据密集的工具界面要的是同样的面积里
  多放一行信息。

**3. 背景安静下来。**
默认主题（深空）的 `fx` 从 `true` 改成 `false` —— 不再挂
WebGL 透视网格和星尘；CSS 层那张 34px 的方格网也只在
`html[data-fx="on"]` 时渲染（只有赛博绿一个主题开）。
登录页的三团 46rem/38rem/34rem 漂移光斑换成一层静态渐变。

> 没有删掉这套特效 —— 赛博绿仍然开着。**想要那个感觉的人可以选它，
> 但默认主题应该是安静的。** 这是"提供选项"和"强加风格"的区别。

**4. 文案去口号。**
`"按优先级排好了：先清复习队列，再补错题，最后学新内容"`
→ `"按到期时间排的"`；
`"沿知识依赖图回溯，找的是根因而不是症状"`
→ `"沿依赖图往前找，找到能一次解开多个问题的那一个知识点"`；
`"建班、建号、布置作业、看学情根因，全流程闭环"`
→ `"建班、建号、布置作业、看学情"`。

规律是：**原文在向用户解释"我做了什么"，而用户看到的本来就是
已经做好的结果**。真实产品只在用户**会误解**的地方解释，
其余地方让内容自己说话。"全流程闭环"这类词更是纯商业黑话，
它不传达任何信息。

**改完之后怎么验证**：不是"我觉得好看了"，而是那几条可数的指标
降下来了 —— 玻璃面从 125 处降到 16 处（且全部在真正的浮层上），
渐变 46→4，发光 49→1（只剩焦点环）。这些数字可以随时重新数：
按类名 grep 一遍就知道有没有回潮。

#### 自研 Markdown 渲染器：为什么顺序不能换

标记漏屏（气泡里看到裸露的 `**` 或 `$`）是这类渲染器最典型的缺陷，
而且**页面不报错、测试全绿**。根因几乎都是解析顺序错了。
所以本实现的顺序是固定的三层：

```
① 分块   先切出代码块，代码块内部**不做任何行内解析**
② 行内   在非代码块的文本上做，且行内代码优先于粗体
③ 数学   最后处理 $...$，避免 $ 被当成普通字符吞掉
```

另外：**从设计上就不产生 HTML 字符串**（除了 SQL 高亮那一处，
它自己做了转义），全部走 React 元素，所以没有 XSS 面。

#### SQL 编辑器：透明 textarea 叠在高亮层上

不引 CodeMirror（200KB），做法是：

```
底层  <pre>       放着高亮后的 HTML，不可交互
上层  <textarea>  真实输入，文字**透明**、光标可见（caret-color）
```

两层必须像素级对齐。**对齐只有一次机会做对** ——
字体族 / 字号 / 行高 / letter-spacing / tab-size / padding / border /
white-space 全部一致，所以它们统一写在 `SHARED` 常量里，两处都引用它。
分别写两遍的话，改一处忘另一处就会错位，而症状是「打字时光标飘」，
很难联想到是 padding 差了两像素。

#### 日期口径：为什么不能用 `toISOString()`

`new Date().toISOString().slice(0,10)` 是 **UTC 日期**。
北京时间 2026-10-01 早上 07:00 时，UTC 还是 09-30，
于是「今天做的题」会被记到昨天头上：连续打卡断掉、每日目标重置。
这个 bug 只在 00:00–08:00 之间出现。

所以全站统一：业务口径的「今天」= **服务器本地时区的 YYYY-MM-DD**。
审计用 epoch ms，两者并存、互不推导。

### 3.4 内容层

内容不是代码，但它决定了系统有没有用。全部课程内容放在
`server/src/data/` 下的 ES 模块里（不用 JSON —— SQL 里的换行和引号
在 JSON 里是转义地狱，而模块支持注释，能写清每个数据集的业务背景）。

| 文件 | 内容 | 量 |
|---|---|---|
| `catalog.js` | 分类 → 章 → 知识点，含 Markdown 正文 | 7 分类 / 29 章 / **43 知识点** |
| `edges.js` | 有向依赖边（prereq / related / confusable） | **68 条** |
| `datasets.js` | 教学数据集（DDL + 样本数据 + 结构化元信息） | **4 套** |
| `levels.js` | SQL 关卡（含可执行的参考答案） | **45 关** |
| `questions.js` | 客观题（五种题型） | **74 道** |
| `normalize.js` | 范式题（四种问法） | **15 道** |
| `labs.js` | 索引实验 + 事务实验 | **9 个** |

**四个教学数据集**：学生选课库 / 电商订单库 / 图书借阅库 / 员工部门库。
选它们的理由是「学生一眼能看懂业务含义」——
抽象的表名（T1/A/B）会让学生把认知预算花在「这列是什么」上，
而不是花在 SQL 本身。

**依赖图的质量直接决定诊断的质量**。边连得太粗（什么都连），
根因会一路回溯到最顶上，建议没有可操作性；连得太细，
症状和病灶会脱节。判断标准写进了文件注释：
**「学 A 之前不学 B 会不会真的学不懂」** ——
会，才是 hard prereq；只是「有点吃力」，是 soft。

### 3.5 数据模型

**核心不变式：明细表是权威，聚合表只是加速层。**

- `attempts` **全量保留**，永不裁剪
- `stats_node` / `stats_daily` 纯属加速，任何时候都能用
  `rebuildStats(userId)` 从明细完整重建
- 代价是每次作答要写 4 张表 —— 所以整个作答流程包在**一个事务**里，
  避免「题算对了但 XP 没加上」这种偏账

28 张表分七层：

```
账号      users / sessions / auth_log / user_settings
班级      classes / class_members
内容      categories / chapters / knowledge / knowledge_edges /
          questions / datasets / sql_levels / normalize_tasks / labs
学习      attempts / stats_node / stats_daily / sql_runs / notes / cards / checkins
作业      assignments / assignment_items / submissions
游戏化    game_state / achievements
审计      admin_log
```

**两处刻意的设计**：

1. **题库和关卡分成两张表**。客观题判分是字符串比对，
   SQL 题判分是跑两遍比结果集。后者需要数据集、参考语句、
   是否计较行序三个额外字段，而且判分要走 worker 沙箱。
   塞进一张表等于让所有客观题判分路径都背上这三个字段和一条异步分支。

2. **作业提交存快照**，不实时回查 `attempts`。
   学生交卷后还会继续刷题，实时回查会让一份已批改的作业
   随着他继续练习而「变分」。快照是契约，`attempts` 是流水。

### 3.6 测试

十一组，全部零依赖（Node 内置能力 + Chrome CLI），从快到慢：

| 组 | 数量 | 测什么 |
|---|---|---|
| **内容自检** | 全部内容 | 45 关的参考答案**真跑一遍**、15 道范式题用自带答案反验、9 个实验台真跑 `EXPLAIN` / 真算优先图、依赖图环检测、所有文案字段必须是字符串 |
| **单元测试** | 179 项 | SQL 切分与闸门、结果集比对、范式算法、FSRS、图谱与诊断、客观题判题、游戏化，**以及前端两个渲染器的 XSS 转义与标记漏屏** |
| **接口冒烟** | 194 项 | 起真服务跑完整流程：注册→建班→入班→学→练→判→复习→作业→批改→权限边界 |
| **加固回归** | 34 项 | 安全响应头、限流、5xx 不泄露内部信息、SQL 沙箱逃逸尝试、SPA 回退、越权返回 403 |
| **主题对比度** | 144 项 | 10 套主题的四级文字色是否过 WCAG AA、强调色是否过 3:1、层级有没有塌（纯静态） |
| **古风字体** | 20 项 | 字体资产与 CSS 双向对齐、楷体栈有系统兜底、注册表与样式表一致、`unicode-range` 不重叠（纯静态） |
| **AI 纯函数** | 60 项 | 表达式求值器、出题清洗不变量、教学阶段状态机、工具白名单 |
| **AI 配置规则** | 30 项 | 全局配置继承 / 自助注册不继承 / 个人覆盖 / 权限边界 |
| **AI 端到端** | 17 项 | 多智能体课堂 / 工具调用 / 出题入库 / 讲评（mock 上游） |
| **浏览器冒烟** | 23 项 + 23 页截图 | 真浏览器逐页断言 + 交互断言 + 截图（**需要能跑无头浏览器的环境**） |
| **AI 课堂冒烟** | 17 项 | 真浏览器跑一节 AI 课：开课 / 作答 / 黑板 |

**内容自检为什么要单独一组**：它检查的不是代码，是内容。
这类错误的症状是「学生写对了却被判错」，而代码测试一条都查不出来。

**为什么前端渲染器在单元测试里测**：它们看起来「是 UI」，
但核心是纯字符串处理，而最容易出的缺陷恰好在这一层
（SQL 高亮忘了转义 → XSS；Markdown 解析顺序错 → 标记漏屏）。
这两类问题页面不报错、截图看不出来、接口测试更测不到。

**主题对比度 / 古风字体为什么各占一组**：它们守的是同一类东西 ——
**不会报错、不会让截图变难看的缺陷**。对比度低了页面照样渲染；
字体掉回黑体截图照样清晰。只是学生看不清 / 古风没了。

> ⚠️ **这两组一度没接进 CI**。它们写在 `tests/run-all.mjs` 里，
> 而 CI 是逐个列 `npm run test:xxx` 的，漏掉了它们。
> 后果很实在：古风主题「砚秋」的文字色是深色压在深色底上
> （对比度 1.50:1，字基本看不见），CI 全绿、PR 全绿，
> 一直到有人肉眼看才发现。**测试写了不跑，等于没写。**
> 现在两个 `test:contrast` / `test:fonts` 都在 `ci.yml` 里。

> ⚠️ **浏览器那组在本机跑不起来**。Chrome 的进程沙箱在这个环境里
> 初始化失败（Operation not permitted），加 `--no-sandbox` 之后
> 进程又会被外层杀掉；CDP 的页面级 WebSocket 通道也被阻断
> （浏览器级能连、命令有响应，页面级握手后立刻 1006）。
> 三条路都试过，所以脚本检测到跑不了会**明确跳过**，不假装通过。
> 在有桌面环境的机器上它会正常出图并断言。
>
> 补充：**Chrome 主程序跑不了，但 `chrome-headless-shell` 能跑**
> （Playwright 缓存里那个二进制）。本机的截图和古风断言就是用它出的。

## 三·五、AI 课堂（多智能体）

### 为什么 agent loop 在服务端

一个自然的疑问：为什么不把 loop 放在浏览器里？

因为**工具要读的数据在服务端**。库课的考点、题库、作答记录、判分器全在 SQLite 里 ——
让浏览器去查库既查不到也不安全。所以 loop 在服务端，前端只收事件流
（一条 SSE 连接撑一整节课，挂起等作答期间连接不关，答案 POST 回来接着走）。

顺带一个好处：密钥连「转发」这一步都不需要。

### 四个角色靠机制区分，不靠形容词

这是多智能体最容易做砸的地方。只写「你是个聪明学生」「你基础不好」，
模型会说出几乎一样的话 —— 所有 agent 收敛到同一种腔调，机制退化成噪音。
**差异必须来自结构，不是形容词。**

| 角色 | 拿到的资料 | 典型失误 |
|---|---|---|
| 陈老师 | 正文 + 示例 SQL + 依赖 + 常见错误 + **学情数据** | —— |
| 林一鸣（优等生） | 正文 + 示例 SQL + 依赖 | **结论下得太早**（不验边界条件） |
| 周雨桐（中等生） | 正文 | **条件用错**（WHERE/HAVING、NULL 语义） |
| 马小虎（后进生） | **只有一句摘要** | **概念混淆**（主键 / 唯一索引） |

关键在于第三层**工具白名单**：学生手里**没有** `write_sql`（写完整解答的能力）。
会跑 SQL 不等于会写解法 —— 这条边界靠提示词约束不住，只能靠工具表约束，
而且写成了**模块级断言**（`tools.js` 末尾），import 就会炸。

测试直接断言**发给上游的请求体**：三份学生提示词两两不同，
且林一鸣的资料明显比马小虎多 200 字以上。

### 教学阶段由代码持有

模型除了对话历史不持有任何状态。每轮把全部规则平铺给它，它会按
「每轮要留一道题」这种惯性继续走 —— 即使这一轮的情况完全相反。

| 阶段 | 进入条件 | 谁能说话 | 结尾留什么 |
|---|---|---|---|
| `lecture` | 第 1 轮 | 老师 + 同学 | 回忆式问题 |
| `explain` | 常规讲授 | 老师 + 同学 | 回忆式问题 |
| `clarify` | 他说「没听懂」 | **只有老师** | **理解确认（禁止出题）** |
| `practice` | 他说「懂了」 | 老师 + 同学 | 一道小题 |
| `discuss` | 研讨模式 | 老师 + 同学 | 开放问题 |

意图分类的**顺序就是语义**：先判困惑再判懂了。
「听不懂」「没听懂」里都带一个「懂」字 —— 反过来判的话，
「我还是没听懂」会被归成「听懂了」，下一轮直接甩一道题出来。
这条有回归断言钉着。

**提示词是请求，硬过滤才是保证。** 模型输出之后要兜：
`clarify` 阶段把非老师角色的发言全部摘掉（而且**根本不调**它们 —— 省 token）；
结尾若是动手题就换成理解确认；没有结尾问题就补一个。三种越界都如实上报给前端。

> 这里踩过一个坑：判断「算题」不能只看结尾的问句。
> 「好，那你写一条查询看看：SELECT ... 会返回几行？」里，
> 动手信号在**冒号前面那句引出语**里，抠出来的问句本身不含它。
> 所以判据和替换用的是**同一个 span**（引出语 + 问句）。

### 黑板是一串动作，不是一张图

| 动作 | 给谁 | 效果 |
|---|---|---|
| `run_sql` | 老师 + 学生 | **在真实教学库上执行 SQL**，结果表上黑板 |
| `explain_plan` | 老师 + 学生 | 执行计划，讲索引时用 |
| `draw_graph` | 老师 + 学生 | 函数图像，参数可拖，讲复杂度曲线 |
| `write_steps` | 只有老师 | 解题步骤（上限 8 条），逐条错开落下 |
| `write_sql` | 只有老师 | 标准 SQL（带高亮）—— 这是「写完整解答」 |
| `highlight` | 老师 + 学生 | 圈出已有某一块（按**文字**匹配） |
| `new_page` / `clear_board` | 只有老师 | 翻页 / 擦除 |

所有动作返回**同一个形状** `{type:'board', item:{kind,…}}`，渲染层只认 `kind`。
`highlight` / `page` / `clear` **不占黑板块数的号** —— 这个口径是
「增量动画记账」和「highlight 找目标」两处的唯一来源，不一致就会
出现「该播动画的块不播」这种静默失效。

### 不让用户当观众

多角色 agent 集群最容易犯的错是：四个 agent 聊得热闹，用户在旁边看。
那不是上课，是一档节目。判断标准很简单 ——
**整场下来有没有任何一步要求他动手？**

所以每一轮结束都挂起等作答。挂起是纯本地等待，不花 token，收益却是全部。
配套的三条门禁：

1. 等作答期间**关掉插话入口**，并写清为什么（「先把上面那道题交了，再插话」）
2. 一键「还是没懂 / 懂了，继续」**两个按钮都要有** —— 少一个这条链就断了
3. 收尾后插话入口回到「禁用 + 说清为什么」，不留一个点了只弹错的框

### AI 出题：模型生成的东西要交给程序判分

库课的判题器只认这几种形状，所以清洗函数就贴着它写：

| 题型 | 能收的答案 | 判分方式 |
|---|---|---|
| `choice` | 单个字母 A–D | 严格相等 |
| `multi` | 字母组合（去重排序） | 全对 100，漏选 50，选错 0 |
| `judge` | T / F | 严格相等 |
| `blank` | **纯数值或分数** | 数值容差 |
| `short` | —— | **不自动判分，生成时一律不收** |

两道防线：提示词写死边界 + 清洗函数兜底。测试用**不变量**：
「只要产出了题，它就一定是判得了分的」，再喂一组全是坏形状的输入。
还要**手工写一个不做校验的错误实现**，确认不变量抓得住它 ——
一个永远为绿的检查比没有检查更糟。

> 踩过一个缝：`blankIssue` 认 `x=2`（数值解析会剥掉 `x=`），
> 但入库时只做了 trim，于是库里存的是 `x=2`，学生答「2」被判错。
> **一道标准答案本身判不了分的题进了库，而且没有任何报错。**
> 通则：校验函数和归一化函数必须共用同一个「什么算合法」的定义。

## 四、和参考项目的关系

### 直接照搬的（经过验证的骨架）

| 来自 `kaoyan-math-tutor` | 为什么照搬 |
|---|---|
| 单仓三包（server / web / tests）+ npm workspaces | 边界清晰，一个 `npm test` 跑完全部 |
| 服务端会话鉴权（不用 JWT） | 「强制下线」和「重置密码踢会话」是刚需 |
| 逐路由显式挂 `preHandler` | 「以为挂上了其实没挂」是这类代码最典型的失效方式 |
| 403 而不是 404（越权） | 防止 403 变成存在性探测器 |
| 最后管理员护栏 | 不能让系统失去最后一个管理员 |
| 全量审计日志（含前后值） | 教师端有删学生的权限，没审计就查不出是谁干的 |
| 有向依赖图 + 根因回溯 | 把「症状」翻译成「病灶」的核心 |
| FSRS-6 间隔重复 | 权重逐个数抄自 ts-fsrs，没有凭记忆编数字 |
| 聚合表可从明细重建 | 明细是权威，聚合是加速层 |
| 多主题用 CSS 变量而非 JS 注入 | 首屏不闪 |
| 零依赖测试（CDP / Chrome CLI） | 不背 Playwright 那 150MB |
| 内容自检单独一组 | 内容错误的症状是「学生写对了却被判错」 |

### 改动或新增的

| 项 | 参考项目 | 本项目 | 为什么 |
|---|---|---|---|
| 学科 | 数学 | 数据库 | — |
| 核心交互 | 公式实验室（参数化演示） | **SQL 实训场 + 可执行判题** | 数据库能真跑，那就真跑 |
| 判题 | AI 批改主观题 | **跑结果集 / EXPLAIN / 优先图 / chase 矩阵** | 引擎能给确定答案，不需要模型 |
| 角色 | user / admin | **student / teacher / admin** | 需求是「老师对学生有完全管理权限」 |
| 权限范围 | 管理员管全部 | **教师只管自己名下的学生** | 多教师部署里，「管全部」就是越权 |
| 数据结构 | 知识点 + 边 | 知识点 + 边 + **数据集 + 关卡 + 范式题 + 实验台** | 数据库的练习形态更多样 |
| 内容管理 | — | **内置内容只读、自建内容可改** | 内置内容是判题基准的一部分 |
| 主题 | 8 套 | **10 套**（含 2 套古风：砚秋夜读 / 砚晨晨窗） | 沿用机制，配色按数据库课程的调性重做；古风主题额外换楷体 |
| 渲染器 | KaTeX（数学公式） | **自研 Markdown + SQL 高亮** | 关系代数符号是单字符 Unicode，引 KaTeX 不划算 |

### 一条明确的取舍

参考项目用 AI 批改主观题（解答题/证明题没法自动判分）。
本项目**没有引入任何 AI 能力**，理由很直接：

数据库这门课的绝大多数题**有确定答案**，而且这个答案能由引擎算出来。
引入一个概率性的模型去判一个确定性的问题，是给自己找不确定性 ——
而且学生会看到「同一份答案两次给的分不一样」。

只有简答题（如「解释部分依赖和传递依赖的区别」）需要人工批改，
那由教师批改，本来就该由人做。

## 五、已知限制

诚实列出来，不藏：

1. **浏览器测试在本机沙箱跑不起来**（见 3.6 的说明）。
   代码完整，需要真实桌面环境验证。

2. **SQL 方言是 SQLite**。教学用语法它全有，但 `ALTER TABLE`
   支持有限（只能 ADD COLUMN / RENAME），
   MySQL 的 `MODIFY` / `DROP COLUMN` 用不了。
   课程内容里已经点明了这个差异，但没有做多方言适配。

3. **Docker 部署配置未在本机验证**（这台机器没装 Docker）。

4. **内容量够一学期但不富余**。43 个知识点、45 关、74 道客观题 ——
   覆盖数据库系统原理的完整大纲，但每个考点的题量不大。
   想扩充的话，`server/src/data/` 下加条目即可，
   `npm run test:content` 会立刻告诉你新题的参考答案能不能跑通。

5. **教师端的「内容管理」只做了增删改题目**，没做可视化编辑器。
   加知识点 / 关卡要走 API。内置内容刻意设为只读。
